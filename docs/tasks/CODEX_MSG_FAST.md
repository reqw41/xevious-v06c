# Codex: ускорить непрозрачные надписи (ветка msgbox)

Worktree xevious-v06c-codex2, ветка **msgbox** (38331d2 = main d35ff22 + черновик надписей). Здесь можно менять src/
(архитектор в этой ветке не работает), но не коммить: патч build/codex/msgfast/*.patch + REPORT.md.

## Что есть
Надписи «PLAYER ONE / READY», «GAME OVER» (src/vec/msgbox.asm, text_pl.asm msg_one, text_lo.asm msg_flip; вызовы в
src/vec/sprites.asm flush .e2): светлые буквы (VPAL 1: E=1, C=0) с чёрной кромкой 1 точка (8 соседей), фон под
надписью сохраняется в MSG_BUF и возвращается в следующем flush; надписи между стиранием и выводом спрайтов.
Надпись стоит на экране, поле едет: каждое обновление она сдвигается на 1 строку памяти (строка верха +1).
Вид правильный (build/s15/msg-final.png), lockvec 0, hangcheck 12/12.

## Проблема
~85k тактов на обновление с надписью (msg_one ~66k: расчёт кромки .pc ~22k, копия знака .cg ~6k, вывод .row ~30k;
msg_restore ~19k). READY идёт после каждой гибели, поэтому обычная игра lockvec seed 3: 8276 -> 9324 кадров
(+12,7%). god 7/3/11: 8455/8360/8428 -> 8543/8449/8513.

## Цель
Вид тот же (или почти: кромка вокруг букв, сплошной светлый цвет). Стоимость — не больше старого XOR-варианта
(~25k на обновление; main d35ff22 — эталон темпа): lockvec обычная seed 3 и god 7/3/11 — не хуже main более чем на
0,5%. Память: свободно ~56 Б внизу (до 3C00h), ~44 Б в окне карты (до 6000h), POOL 849 (минимум 840), окна
3FF4h/89F4h по 12 Б; запас загрузчика до 8000h ~10 Б (tools/vecboot.js — несжимаемые данные опасны, сжимаемые — ок).
Идеи (проверь замером): кеш кромки/знаков при появлении строки (строки постоянны всё время показа), сдвиг на строку
вместо полного восстановления (фон новых 8 строк уже в буфере — сохранять/восстанавливать по одной строке, выводить
из буфера), развёртка, хранение ~кромки только для букв этих трёх строк (их 12: P L A Y E R O N D G M V) таблицей
при сборке, общий проход двух плоскостей, отказ от пустых строк/пробелов.

## Проверки
lockvec god 7/3/11 + обычная seed 3 — 0 расхождений, темп (см. цель); hangcheck 1..12; hudcheck; снимки READY и
GAME OVER на модели из build/xevious_boot.rom (как build/s15/msg-final.png) — вид не хуже; после исчезновения
надписи поле чистое (без следов); сборка загрузчика проходит.
