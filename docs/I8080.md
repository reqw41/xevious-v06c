# Перенос логики в i8080 (этап 4)

Источник — JS-модель `src/model/` (сверена с Z80). Код — `src/i80/*.asm`, синтаксис Z80 с командами i8080
(`tools/vendor/asm.js`). Каждая процедура i8080 сверяется с Z80 тем же стендом `tools/cpc/oracle.js --i80`:
на том же снимке входа, что и JS, исполняется код i8080, сравниваются записи в память, выходные регистры, снятие
со стека и вызовы платформы.

## Соглашения

- **Вход/выход — как у Z80**: те же регистры (A, L, HL…) и аргументы на стеке, вызываемая снимает их сама.
  Так сверка прямая; ускорять соглашения — потом, процедура за процедурой, со сверкой.
- **Метки**: процедура модели `имя` → `p_имя`; вход платформы `имя` → `plat_имя` (в сборке для сверки —
  заглушки `ret`, в игре — вывод Вектора).
- **Состояние игры по адресам CPC.** Переменные 3C00h–3FFFh лежат на Векторе там же, это блок `VARS`.
- **Самоизменяемые операнды CPC — обычные переменные** (таблица `SELFMOD` в `src/i80/layout.asm`, перевод адресов
  для стенда — `tools/cpc/run80.js`).
- **Карта** (банк 6 CPC, окно 4000h–7FFFh: тайлы и наложение) — с адреса `MAP`.
  Буфер строки карты B582h — `ROWBUF`.
- **Только для CPC, не переносится**: регистр I (конфигурация памяти; операнды 1EA1h/1EEDh/1F21h), этапы
  прерывания с OUT, перемигивание байтов в коде рисования.
- **Таблицы-константы CPC** (пути, волны, флаги, строки) — `build/gen/cpc_tables.inc`, извлекаются из disc.bin
  при сборке (`tools/i80build.js`), метка `T_<адрес>`. Данные оригинала в репозиторий не кладутся.
- **IX/IY Z80** → HL/DE и указатели в памяти.

## Сборка

`node tools/i80build.js` → `build/logic.rom` + `build/logic.json` (метки). Сверка:
`node tools/cpc/oracle.js --i80 [--god] [--area N] …` — для процедур, у которых есть `p_имя`, второй ряд итогов
«i80».
