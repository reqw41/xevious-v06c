# Журнал

## 2026-11-17 — старт

Что известно со страницы CPC-Power (fiche 20000):
- CPC 6128, нужны 128K (Extended RAM); на 64K выдаёт «FAIL TO LOAD RAM».
- MODE 1 (4 цвета), лишние цвета даёт смена палитры по строкам (растры).
- Экран уменьшен: CRTC R1=32 (256 точек MODE 1 = 64 байта в строке), R6=29+2 строк символов.
  Поле около 256×224 плюс две строки счёта внизу (1UP / HIGH SCORE / AREA).
- 8 зон, идут по кругу. Шумовые эффекты есть, музыки в игре нет (Nomusic); Arkos в титрах, вероятно, для заставки.
- Данные сжаты ZX0.
- Управление: CTRL — выстрел, SHIFT — бомба, P — пауза; 1/2/3 в меню выбирают бонусную жизнь.

Почему подходит Вектору: ширина 256 точек совпадает с экраном Вектора, вертикальная прокрутка
на Векторе аппаратная (порт 03), 16 цветов из 4 плоскостей покрывают растровые цвета CPC.
Главный вопрос — память: 128K на CPC против 64K на ванильном Векторе (плюс квазидиск, если он есть).

Скриншоты: ref/cpc/shot1..4.png, fiche_64k.png.
Образ DSK закрыт капчей на сайте: скачать вручную в ref/cpc/.

Инструменты для CPC уже есть в ~/projects/aticatac-v06c/tools (dskextract.py, cpc6128.js, cpcshot.py, akgflat.py).

### JS-эмулятор CPC (17.11, ночь)

`tools/cpc/`: cpc6128.js (модель), dsk.js (файлы из DSK), png.js, run.js (прогон без окна), vendor/Z80.js.
Прошивки нет: BC77/BC83/BC7A читают файлы прямо из ref/cpc/xevious.dsk, KL-вызовы — пустые.
CRTC по строкам (VCC/VLC/R4/R5/R7/R9, гашение на VCC==R6 до конца кадра), строки выводятся с текущей
палитрой. Скорость ~270 кадров/с. Пример:

    node tools/cpc/run.js --frames 1400 --hold "100-110:J_FIRE1,900-1300:CTRL+SHIFT" --every 100 --from 100

Снимки 384×312 в ref/cpc/jsnaps (поле игры — x 64..320). Результат совпадает с MAME.

Что показал эмулятор:
- Кадр CRTC разорван на два: поле 28 рядов (224 строки) и панель 2 ряда (R4=8, R5=8, R6=2) с адреса 0x2000
  (страница 0x8000), панель не прокручивается.
- Двойной буфер подтверждён: поле по очереди со страницы 1 (ma 1xxx) и страницы 3 (ma 3xxx).
- Прокрутка рядами CRTC: начало поля уменьшается на 0x20 (ряд = 8 строк) примерно раз в 8 кадров.
  Как сделана плавность внутри ряда — разобрать.
- На титуле перо 3 меняется по строкам (растры логотипа).

## 2026-11-18 — разметка по смыслу, слой 1

Инструменты:
- `tools/cpc/callprof.js` — профиль вызовов на модели CPC: вызовы и команды на кадр (своё и с вложенными), записи в экран, кто кого зовёт. Аргументы через стек и возврат `pop hl; jp (hl)` учтены (возврат определяется по адресу, не по SP).
- `tools/cpc/spritecat.js` — на каждом вызове примитива вывода вырезает экран вокруг (X, Y) из памяти по таблицам строк A300h/A400h. Листы картинок — `build/cov/sprites/<процедура>_<примитив>.png`.
- Смысл — `src/cpc/disc_notes.py` (метки, заголовки, описания, переменные). `tools/ctlpatch.py` вливает его в ctl при `skool.py build`.

Устройство:
- **Прерывание** 047Dh — цепочка из 6 этапов: `jp (hl)`, адрес в самой команде (0481h). Этапы:
  1. R5/R12/R13 и перья поля;
  2. счётчик кадров;
  3. R4/R5 под панель;
  4. звук (банк 4);
  5. адрес панели;
  6. клавиатура, мигание, пауза.
- **Главный цикл** 3AAFh, раз в 2 кадра:
  1. ждать кадр;
  2. стереть все объекты в заднем экране по координатам прошлого обновления (камера 3F27h);
  3. строка карты;
  4. волны по таблице зоны 02B3h, камера 3E4Ch, игрок;
  5. обновить и вывести объекты;
  6. корабль игрока;
  7. смена экранов 1627h.
- **Координаты** объектов хранятся парами по двум экранам: индекс 3E51h — задний экран, 3E52h — передний.
- **Типы объектов** — пары процедур: стереть плюс столкновения, затем движение плюс вывод.
  - 2A91h/2B5Bh — снаряды врагов, рисуются кодом (0CABh);
  - 287Eh/292Ah — волны из таблицы;
  - 1B1Ah — наземные цели из тайлов карты (1F60h);
  - 2BE9h/2CCBh — воздушные враги;
  - 23A4h/23F5h — выстрелы игрока;
  - 2F52h/2F8Dh — корабль и бомба.
- **Примитивы вывода:**
  - 0EFDh — спрайт с маской и отсечением;
  - 1334h — вернуть фон 16 строк;
  - 0EAEh — знак надписи;
  - 1219h — блок 2×8.
- **Столкновения:** 17E3h (с игроком), 181Bh (16×16). Очки — 27DFh (BCD 3F24h).

### Слой 2
- **Спрайты `xeviouss.dat`** (с 8080h): по 256 байт на объект. Это 128 байт рисунка (16 строк × 4 пары «маска, рисунок» MODE 1) и 128 байт той же картинки со сдвигом на 2 точки для нечётного X.
- **Кто какие спрайты выводит:**
  - корабль — #0, гибель — #6/#7;
  - прицел — #1 (3C46h);
  - воздушные враги (2CCBh) — #0, 2–4, 8–12, 17–19, 26;
  - объекты таблицы зоны (292Ah) — #5, #16, #24.
- **Таблица 02B3h** — наземные объекты по строкам зоны. Записи по 4 байта [строка, X, тип, флаг], 8 на зону.
- **Кто заводит особые объекты:**
  - 2032h — зоны 2–3 (слоты 3E60h);
  - 18B8h — зоны 4 и 8 (3E3Ah);
  - 1904h — воздушные враги в начале зоны;
  - 1878h — сбиваемые снаряды, каждые 8 строк.
- **Гибель** 3817h: счётчик 3F1Bh, через 40h обновлений — минус жизнь, затем конец игры (378Ch) или рестарт (3438h).
- **`ctlpatch.py`** теперь перезаписывает и метки, не только заголовки.

### Слой 3: карта и звук
- **Карта** (банк 6, `xevlevel`): 0000h–1FFFh — номера тайлов, 64×128. 2000h–3FFFh — слой наложения той же формы. Значения наложения:
  - 40h — пусто;
  - меньше 40h — тайл наложения из банка 5 (`xeviougt` + 1000h, по 64 байта), нулевые байты прозрачны;
  - 41h — место особого флага;
  - 17h/19h/23h/25h — наземные цели (1F60h).
- **Тайлы фона** — банк 7 (`xeviousg`), по 64 байта. С 2800h там лежат крупные картинки наземных объектов (13DFh).
- **`xeviougt`**: 0000h–0FFFh — логотип титула (1552h), с 1000h — тайлы наложения.
- **16B6h** выводит одну строку точек над верхом экрана: заливка, затем 15 тайлов, затем наложение. Вызывается дважды за обновление.
- **Звуковой драйвер** — проигрыватель Arkos Tracker 1 (модули «AT10») с эффектами. Модули:
  - 4800h — музыка игры;
  - 4900h — эффекты;
  - 4B00h — заставка жизни;
  - 4C00h — конец игры.

  Для Вектора можно перенести сам проигрыватель на i8080 под AY или переложить модули в свой формат. Модули остаются те же.

## 2026-11-18 — этап 3: JS-модель логики, сверка с Z80

**Стенд** `tools/cpc/oracle.js` работает на модели CPC. На каждом входе в процедуру, для которой есть JS, Z80 исполняет её до
возврата, а JS — на снимке памяти входа. Сравниваются записи в память (без экранов), выходные регистры, снятие
аргументов со стека и вызовы платформы по порядку.
- **Снимок входа:** прежние значения байтов, которые меняет Z80. Байты, что Z80 прочёл до своей записи, JS берёт
  прочитанными. Так видны правки прерывания посреди обновления (джойстик 3D42h).
- **Граница с платформой** — `src/model/platform.js`: вывод (спрайты, фон, тайлы, надписи), звук, ожидание кадра.
  Внутри этих вызовов записи не сверяются. Пока там же `restart_life` и `game_over`.
- **Ключи:** `--god` (без гибели — для охвата дальних строк зон), `--poke`, `--only`. Отладка — `DBG`, `DBGT`, `DBGW`.

**Модель** — `src/model/*.js`: 60 процедур. Это главный цикл 3AAFh целиком и всё, что он вызывает:
- корабль, выстрелы, бомба;
- прокрутка, строка карты, переход зоны, флаг, база Андор;
- наземные цели, объекты таблицы зоны, пули, сбиваемые снаряды, воздушные враги;
- особые объекты зон 2–3 и 4/8;
- гибель, очки, рекорд.

**Что выяснилось по ходу:**
- **Маски кнопок** — операнды AND в коде (2FF0h и др.). Их ставит выбор управления при старте (326Eh).
- **Самоизменяемые операнды — часть состояния:**
  - 0745h — зерно `rnd`;
  - 280Ch — порог доп. жизни: 20000, затем каждые 70000;
  - 2454h — скорость выстрела;
  - 1A21h — NOP/RET: стрельба целей включена или нет;
  - 1B4Ch, 185Bh, 1868h, 1C77h…1C84h — зона поражения бомбы по базе Андор;
  - 1F8Eh, 2999h, 389Fh — усложнение на втором круге;
  - 267Ah — случайный сдвиг флага.
- **Выбор волны** зависит от строки зоны: выше 24h — воздушные волны, ниже — особые объекты зоны или снаряды.
- **Причуды оригинала**, повторены как есть:
  - `spawn_air_start` сравнивает X игрока по номеру слота;
  - `erase_air` берёт выстрелы без смещения экрана.

**Итог сверки:**
- 8 зон × 8000 кадров, `--god`: ни одного расхождения, включая главный цикл.
- Обычная игра: расхождения только в обновлениях с перезапуском жизни, его ещё нет в модели.

**Дальше:**
- `restart_life` / `game_over`;
- логика прерывания: звуковой режим 3D3Ah, клавиатура;
- затем перенос модели в i8080.

### 2026-11-18 (продолжение) — прерывание

  - иначе музыка: по истечении таймера режим −1 и запуск модуля 4800h;
- **этап 6:**
  - перемигивание цветов через кадр: тетрады 12 байтов в коде рисования по таблице 0712h и 6 байтов из 0736h/073Ch;
  - при включённой панели (064Ah) — пауза 3F2Fh: клавиша P при нечётном режиме звука ставит паузу и режим FFh, любой бит 3D42h её снимает.

Остальное в прерывании — OUT в CRTC и палитру, то есть вывод. Опрос ввода `read_input` 1487h (fx: итог в 3D42h и матрицу 3D43h…) и звуковой драйвер — платформа: `snd_play` 400Ah, `snd_fx_a` 475Ch, `snd_fx_b` 4772h, `snd_start` 4707h (вход вне 0000–3FFFh, флаг `hi`).

**Стенд:**
- у каждой сверки своя глубина `qd`: «своими» считаются записи без кадров платформы или прерывания над ней, поэтому этапы прерывания сверяются поверх чего угодно;
- чтения портов внутри сверки отдаются JS по порядку (`m.inp()`), это строка клавиатуры для паузы;
- `--press 'кадр:клавиша'` нажимает клавишу на 4 кадра.

**Итог сверки** — 8 зон × 3 режима (обычная игра с паузой, `--god`, конец игры): ни одного расхождения. Этапы прерывания сверяются на каждом кадре.

**Модель логики полная.** Всё, что меняет состояние игры, переведено в JS и сверено с Z80. Снаружи остались только вывод, звук, ввод и экраны титула и рекордов.
