# Платформа Вектора (этап 5): память и вывод

Логика на i8080 готова и сверена (`docs/I8080.md`). Здесь — что ей нужно от Вектора и куда всё ложится.

## Бюджет памяти (замер 19.11)

Видимы две плоскости (C000h–FFFFh), остальное — 48 КБ (0000h–BFFFh) под код и данные.
Замер ресурсов — `PLATLOG=файл node tools/cpc/oracle.js …`: все вызовы платформы с аргументами
на 8 зонах × 3 режима.

| что | КБ | откуда цифра |
|---|---|---|
| логика i8080 | 9,9 | `build/logic.rom` (без карты) |
| платформа: вывод, панель, прерывание, ввод, звук, титул | ~6 | оценка |
| тайлы: 171 × 64 Б (151 из карты + база Андора, следы целей, пустые) | 10,9 | замер |
| слой тайлов карты 64×128 | 8 | только чтение |
| наложение карты (вычисляется) | 0,3 | 91 значимая клетка, флаги, база |
| спрайты 16×16 (25) с маской, кадры 8×8 (15), особые объекты (10) | ~6,5 | с половинным сдвигом |
| буферы фона летающих объектов (один экран) | ~2 | ~45 объектов |
| переменные игры 3C00h–3FFFh, стек | 1,5 | |
| музыка и эффекты (ВИ53) | ~3 | оценка |
| шрифт панели, надписи, логотип титула | ~3 | оценка |
| **итого** | **~51** | из 48 |

Не хватает ~3 КБ. Запасы:
- код логики писался для сверки, а не для размера: повторяющиеся `ld a,(i) / ld hl,T / call at_hl_a` можно
  свернуть, ожидаемо −1,5…2 КБ;
- слой тайлов: блоки по 4 тайла — 566 разных, словарь 2,3 КБ + индексы по 2 байта — выигрыш мал;
  сжатие по зонам с распаковкой окна 15×128 при входе в зону — ~5 КБ сжатых + 1,9 КБ окна, выигрыш ~1 КБ;
- тайлы: сжатие с кэшем тайлов зоны (60–80 разных на зону) — выигрыш ~1,5 КБ.

## Наложение карты — вычисляется (сделано 19.11)

Все записи игры в карту идут только в наложение: флаг зоны (41h/40h) и база Андора (коды 10h..33h, 6×6).
Слой тайлов только читается. Под всеми возможными местами флагов и под базами в данных стоит 40h. Значение
клетки (`ovl_get`, `src/i80/map.asm`):
1. список изменённых клеток `OVL_SET` (8 × адрес, код) — то, что игра записала поверх;
2. база Андора — прямоугольник при `ANDOR_SAVED`;
3. значимые клетки из данных (`OVL_IDX`/`OVL_ENT`, генерирует `tools/i80build.js`), иначе 40h.

Запись (`ovl_write`) кладёт клетку в список, если значение отличается от того, что дали бы база и данные, иначе
убирает. Так воспроизводится и тонкость оригинала: на переходе с зоны 8 на второй круг флаг зоны 1 ставится
в клетку под ещё не убранной базой зоны 8, и уборка базы его затирает.

Сверка: каждая запись игры в карту проходит через `hook_mapw` (на Векторе — RET), стенд пишет её как запись
в банк 6 CPC; список стенд собирает из снимка (`tools/cpc/ovl80.js`).

## Отдельный прогон логики (`tools/cpc/lockstep80.js`)

Логика i8080 живёт в своей памяти и сама крутит `p_main_loop`, платформа — заглушки. Снаружи — только байты
прерывания (звук 3D3Ah–3D3Ch, кадры 3D3Dh, 3D3Fh, ввод 3D42h–3D4Ch, пауза 3F2Fh): те значения, что Z80 прочёл за
обновление. После каждого обновления сравнивается всё состояние с CPC. 8 зон × (обычная игра, без гибели) по
10 000 кадров (~4800 обновлений) — 0 расхождений. Конец игры (экраны титула и рекордов — fx) здесь не крутится,
его сверяет `oracle.js`.

## Вывод: один экран вместо двух

CPC рисует кадр в задний из двух экранов: стирает объекты там, где они были два обновления назад
(вызовы `restore_*` с буферами заднего экрана), и рисует заново. На Векторе экран один, поэтому:
- платформа сама ведёт список нарисованного в прошлом обновлении (место, размер, свой буфер фона) и в начале
  следующего стирает всё в обратном порядке, затем рисует новое; `restore_*` летающих объектов из логики —
  пустые;
- `restore_16` с картинкой из банка тайлов (адрес ≥ C000h: следы целей, флаг, пустой тайл) — это не стирание,
  а постоянная правка фона: платформа рисует тайл в фон;
- буферы фона CPC (A880h…BFFFh) — только номера для платформы; надписи `print_text` + `put_blocks` —
  готовые картинки в этих номерах;
- порядок в прерывании — `docs/PORT_PLAN.md` (порт 03 в начале, затем стирание и вывод сверху вниз).
